## 1. What This Project Is

Per its own build spec (`docs/architecture_spec.md`, 1,238 lines — read in full, treated as
*design intent* and cross-checked against real code rather than copied verbatim): **a
portfolio-grade hierarchical multi-agent reinforcement-learning system for optimal execution of
BTCUSDT perpetual futures orders on a limit order book.** Three decision tiers, decoupled by
frequency:

- **L1 — Macro Analyst**: a local LLM (Ollama) reads rolling market features every ~30-60s and
  emits a structured risk-regime JSON signal (`regime`, `risk_score`, `confidence`,
  `urgency_multiplier`).
- **L2 — Strategist**: a continuous-action SAC agent, deciding every 1-10s, paces a parent order
  against a TWAP baseline (participation-rate multiplier + urgency).
- **L3 — Executioner**: a `RecurrentPPO` agent (sb3-contrib, LSTM policy) making a tick-level
  `MultiDiscrete([4, 11, 5])` decision (order type / price offset / size fraction) on every LOB
  update.

**What's actually built (verified against real files, not the spec's aspirational code blocks):**
the full data pipeline (Binance historical + Bybit L2 archive + Binance L1 aggregates), the
Gymnasium environment (`LOBExecutionEnv-v0`) with matching engine and reward function, and L3's
training pipeline through a first-pass smoke test. **What's spec'd but not yet built:** `src/agents/`
and `src/metrics/` are still empty (`__init__.py` only) — no L1 Ollama integration
(`l1_macro_analyst.py`), no LangGraph orchestrator, no stealth-execution wrapper, no metrics
tracker module; `src/train/` has no `train_l2.py`; `src/envs/` has no `wrappers.py`
(`FrozenL3Wrapper`). This matches the project's own phased roadmap — these are Phase 4/5 items,
and the project is currently finishing Phase 3.

**A significant, well-documented pivot from the original plan** (`docs/architecture_spec.md`
§2.1.1): live Binance L2 capture (`src/data/l2_capture_daemon.py`, `scripts/run_l2_capture.py`)
was the originally-planned primary L2 source, but this host's network silently blocks Binance's
*live* API domains (`fapi.binance.com`, `fstream.binance.com`) via SNI filtering — confirmed
directly, not assumed — while the static archive `data.binance.vision` stays reachable. The
project pivoted to **Bybit's public historical L2 archive** (`quote-saver.bycsi.com`, via
`scripts/collect_l2_bybit.py`) as the real, primary L2 source (34GB, 441 days on disk), and to
Binance's `data.binance.vision` *archive* files (not live REST) for L1 aggregate context
(`scripts/collect_l1_data.py`). This is a deliberate, disclosed **cross-venue design**: L2/L3's
order book comes from Bybit, L1's macro context comes from Binance. `l2_capture_daemon.py` is kept
only as a secondary/optional capability.

## 4. File-by-File Breakdown

### 4.1 `src/envs/` — the Gymnasium environment (the core of Phase 2, now complete)

#### `src/envs/matching_engine.py`
Queue-position-aware fill simulation implementing `architecture_spec.md` §2.4, with a documented
extension for actual fill bookkeeping (the spec gives the `Q_ahead` *estimator* formula but not how
fills are determined once it hits zero).

- `QueueState` (frozen dataclass) — `q_ahead`, `own_qty_remaining`, `filled_qty`; `.is_resolved`
  property (true once nothing is left to wait through).
- `queue_position_ratio(state)` — obs idx 13: `-1.0` if no resting order, else
  `q_ahead / (q_ahead + own_qty_remaining)`.
- `update_queue(state, *, v_trade, v_cancel, q_p_before)` — one discrete tick update: cancels
  deplete `q_ahead` proportionally (uniform-random cancel-position assumption) without ever
  filling; trade volume then depletes remaining `q_ahead` first, with any leftover trade volume
  filling the caller's own order. Proven algebraically equivalent to the spec's single combined
  formula (see `tests/test_matching_engine.py::test_sequential_decomposition_matches_spec_combined_formula`).
- `walk_market_fill(qty, prices, sizes)` — level-by-level market-order fill against visible
  top-of-book depth; returns `(fills, qty_unfilled)` rather than inventing a fill price beyond
  visible depth.
- `expected_wait_time(q_ahead, avg_trade_rate)` — returns `math.inf` (by design, not an error) when
  the trailing trade rate is zero.

#### `src/envs/reward.py`
Reward function (`architecture_spec.md` §3.3) and Implementation Shortfall decomposition (§5.1).

- `RewardWeights` (dataclass) — `alpha, lam, beta, gamma, delta, kappa`, all with the spec's
  documented default values.
- `step_reward(w, *, side, fills, arrival_price, mid_price, qty_remaining, qty_total, dt,
  l1_risk_score, canceled_unfilled, queue_ahead_at_cancel, queue_at_level)` — sums slippage penalty,
  spread-capture bonus (maker fills only), inventory-holding penalty (scaled by L1's risk score),
  and unfilled-cancel penalty.
- `ImplementationShortfall` (dataclass) — `fill_ratio, is_exec_bps, is_opp_bps, fees_bps,
  is_total_bps, p_avg`; `is_exec_bps`/`p_avg` are `None`, not `NaN`, when there were zero fills.
- `compute_implementation_shortfall(*, side, fills, qty_total, arrival_price, terminal_mid_price,
  fee_bps_per_fill=0.0)` — the Perold IS decomposition; explicitly special-cases `fill_ratio == 0`
  so the exec-cost term is `0.0` by construction rather than `0 * NaN`.

#### `src/envs/lob_execution_env.py`
`LOBExecutionEnv(gym.Env)` — the full environment, replaying real historical Bybit L2 archive
data. Extensively self-documented with every design assumption and deviation from spec flagged
inline (worth reading directly for anyone extending it — the module docstring alone is ~70 lines).
Currently **Phase 2a/2b scope: L3-only**, single symbol/venue.

- `_OBS_SPEC` — the full 42-dim observation table (index, name, clip range), asserted at import
  time to have exactly 42 entries; every index matches `architecture_spec.md` §3.1.
- `TickView` (dataclass) — one L2 snapshot: best bid/ask, mid, spread, top-N bid/ask price/size
  arrays; `.qty_at_price(price, side)` for depletion-based trade-flow inference.
- Module-level rolling-window helpers (`_rolling_return`, `_rolling_rms`, `_rolling_sum`,
  `_rolling_mean_std`) — vectorized trailing-window statistics, each independently correct for
  arrays shorter than the window (graceful shrink, not a hard requirement).
- `LOBExecutionEnv.__init__(data_dir, horizon_ticks, lookback_ticks, tick_interval_s,
  min_size_mult, max_size_mult, reward_weights, fee_bps_per_fill, date_range, funding_rate_dir,
  l1_risk_score, l1_confidence, l2_urgency, l2_target_slice_ratio_override)` — real constructor
  signature (note: **does not match** `architecture_spec.md` §4.1's illustrative
  `tier=`/`l2_override=`/`seed=` call — `train_l3.py`'s docstring documents this reconciliation
  explicitly).
- `reset(seed, options)` — samples a file + window via `self.np_random`; **`date_range` pins the
  exact file set** so a fixed seed resolves to the same window across separate process runs even
  as backfill adds older files (a real bug this fixes — see `tests/test_lob_execution_env.py`).
  Draws a log-uniform order size relative to the window's median top-of-book depth
  (`min_size_mult`/`max_size_mult`), a random side, and precomputes every rolling-window feature
  series for the whole episode via `_precompute_feature_series()`.
- `_build_obs()` — assembles the full 42-dim vector every step; every index individually
  documented (see the module docstring for genuinely-blocked features like `cancel_add_ratio_*`,
  which are hardcoded `0.0` because the Bybit archive can't distinguish a cancel from a trade at
  the same price — flagged as a real data-source limitation, not a stub oversight).
- `step(action)` — evolves any resting order against tick-over-tick book depletion, decodes the
  `MultiDiscrete([4, 11, 5])` action (HOLD/LIMIT/MARKET/CANCEL_AND_REPLACE), applies it, computes
  `step_reward`, and on episode end adds the terminal `-kappa * IS_total_bps` term.

### 4.2 `src/data/` — data pipeline library code

#### `src/data/features.py`
`mid_price`, `micro_price`, `obi` (now **zero-guarded** — `obi` returns `0.0` when combined
bid+ask volume is zero instead of raising `ZeroDivisionError`), `CancelAddTracker` (still has the
same latent bug as before — see §6), and a new `zscore(x, mean, std, clip=5.0)` helper (returns
`0.0`, not a divide error, when `std <= 0`) used throughout `lob_execution_env.py`.

#### `src/data/split.py`
Chronological train/val/test split generator (`architecture_spec.md` §2.5) — real-file-count based
(not calendar-day based, since Bybit archive gaps mean a calendar window and a real-file count
diverge; confirmed against real data: an 18-calendar-day window had only 7 real files).

- `_discover_present_dates(data_dir)` — parses `YYYY-MM-DD` out of real filenames on disk.
- `_known_gap_dates(present)` — every calendar date between the earliest and latest present date
  with no real file.
- `generate_split(data_dir, split_size=18)` — `test` = most recent 18 real files, `val` = the 18
  before that, `train` = everything older; raises if fewer than `2*split_size+1` real files exist.
- `write_split(...)` — persists to `data/splits/l2_bybit_btcusdt_split.json`; **refuses (raises) if
  a regeneration would change an already-persisted `val`/`test`** — a stability guard since those
  windows are meant to be frozen once backtest work begins.
- `load_split(name)` — reads the persisted artifact; raises if it doesn't exist yet.

#### `src/data/download_manager.py`, `src/data/l2_capture_daemon.py`
Unchanged in essential logic from the bootstrap version (see §6 for the specific bugs/quirks that
persist). Now clearly **secondary/legacy** relative to the newer, actively-used
`scripts/bulk_backfill.py` / `scripts/collect_l1_data.py` / `scripts/collect_l2_bybit.py` trio —
`l2_capture_daemon.py`'s `L2Book`/`apply_diff` primitives are still reused (imported directly) by
`scripts/collect_l2_bybit.py` for its own book reconstruction, so this file is not dead code, just
no longer the primary data-acquisition path.

### 4.3 `src/train/train_l3.py`
Real `RecurrentPPO` training script, reconciled line-by-line against the actual `LOBExecutionEnv`
API (its own docstring documents exactly where `architecture_spec.md` §4.1's reference code was
wrong: no `tier=`/`l2_override=`/`seed=` constructor kwargs; L2-stub-as-fixed-TWAP is already
`LOBExecutionEnv`'s *default* behavior, not something to wire in separately; the training seed
belongs on `RecurrentPPO(..., seed=...)`, not per-env).

- `make_env(date_range, horizon_ticks, lookback_ticks)` — env factory for `SubprocVecEnv`.
- `ValISEvalCallback` — the real validation loop `architecture_spec.md` §4.1's reference code
  lacks entirely. Evaluates against `load_split("val")` only (never `test`), using
  `compute_implementation_shortfall` as the actual business metric rather than SB3's stock
  reward-based `EvalCallback`. **Paired-seed design**: a fixed set of eval seeds (`EVAL_SEED_BASE +
  i`) drives both the once-computed TWAP baseline (from `phase2a_sanity_suite.TWAPPolicy`) and
  every periodic L3 firing, so every reported comparison stays apples-to-apples across the whole
  run.
- `main()` — loads `configs/ppo_l3.yaml`, builds an 8-env `SubprocVecEnv` wrapped in
  `VecMonitor`/`VecNormalize`, constructs `RecurrentPPO("MlpLstmPolicy", ...)` from the config,
  attaches `CheckpointCallback` + `ValISEvalCallback`, trains, and saves
  `models/l3_executioner_v1` + `models/l3_vecnormalize.pkl`. CLI overrides
  (`--total-timesteps`, `--n-envs`, `--eval-freq`, `--n-eval-episodes`) exist specifically to allow
  a fast smoke test before committing real GPU time to the full 20M-step run.

### 4.4 `scripts/` — CLI entry points

#### `scripts/collect_l1_data.py` (712 lines) — **real primary L1 collector**
Pulls klines (1m), funding rate, and open interest entirely from `data.binance.vision` *archive*
files (zip+CHECKSUM), explicitly **not** from `fapi.binance.com`/`api.binance.com` REST endpoints,
because those domains are network-blocked from this host (confirmed via DNS/connection-reset
checks, documented in the module docstring). Handles per-dataset archive-format quirks: klines
tries monthly archives first and falls back to daily files per-month on a 404 or partial-month
request; funding rate is monthly-only; open interest is daily-only and bundles top-trader/taker
long-short ratios for free. Own `Manifest` class (JSONL, same resumable pattern as
`bulk_backfill.py`), graceful SIGINT/SIGTERM handling, and a `_print_summary` that flags (both to
stdout and the log) if any dataset directory exceeds 500MB — an anomaly-detection tripwire for L1
data, which should be small.

#### `scripts/collect_l2_bybit.py` (538 lines) — **real primary L2 collector**
Byte-budget-targeted backfill from Bybit's public `quote-saver.bycsi.com` order-book archive
(500-level snapshot+delta+seq streams). `_discover_most_recent_day` probes backward with
exponential step growth then binary-searches to pin the exact boundary (archive currency drifts,
so nothing is hardcoded). `_process_day_zip` reconstructs book state by reusing
`src/data/l2_capture_daemon.py`'s `L2Book`/`apply_diff` directly rather than reimplementing
book-update logic, adding its own sequence-gap detection one layer up (documented as a correction
to an earlier draft's wrong assumption that `apply_diff` itself checked gaps — it doesn't). Walks
backward day-by-day until a byte budget (default 35GB) or day cap is hit, deleting each raw zip
immediately after writing its Parquet, and stopping early after `max_consecutive_missing` days in
a row (default 14) as a "probably hit the start of the archive" backstop.

#### `scripts/phase2a_sanity_suite.py` (265 lines) — explicitly a throwaway script, not a module
Combines the Phase 2a TWAP baseline and the environment correctness sanity suite (per its own
docstring, "this IS 'Phase 2 done'").

- `TWAPPolicy(n_slices=10)` — passive limit order at the touch per time-slice, forced
  market-order completion if a slice is under-filled by its end. **Reused directly by
  `train_l3.py`** as the eval baseline.
- `NoOpPolicy` — never trades; exists to prove the zero-fill IS edge case is handled correctly.
- `OraclePolicy` — cheats by pre-scanning the full episode window for the single best mid-price
  tick, then executes everything there in one market order; a ceiling check, not a real strategy.
- `run_episode(env, policy, seed, horizon_ticks)` — the shared episode-runner both this script and
  `train_l3.py`'s eval callback use.
- `main()` — runs and asserts: no-op loses *exactly* the opportunity-cost IS term; oracle beats
  TWAP on mean IS; TWAP always fully completes (fill_ratio > 0.999); reports maker/taker fill-share
  breakdown and scenario-difficulty ratios across 50 matched episodes.
